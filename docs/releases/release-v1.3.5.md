## v1.3.5

个人定制版（fork）：接着修 1.3.4 那条线上的最后一个尾巴——**会话起来过又关掉之后，
历史里那行还挂着「已提交，等终端上报」**。

### 问题长什么样

点续跑 → 到终端里信任文件夹、会话起来 → 再把那个会话关掉 → 它回到面板的「最近」
里，却先写着"已提交，等终端上报"，过一会儿才变回可以点的样子。

### 为什么会这样

面板的历史列表是**缓存的**（免得每次会话动一下都去读磁盘），行上"正在等上报"那个
标记是**读盘那一刻**的快照。会话都起来过了，缓存里还拿着旧的"等着呢"，于是面板
照着旧数据画，要等下一次重读才对上。

### 怎么修的

- 不再信缓存里那个标记，**每次刷新面板都现算**"到底有哪些点了续跑、还没报到"。
  现算的时候顺手把"已经被看到活着"的记录清掉——所以**会话只要真的起来过**，
  就不会再被算成待确认。
- 面板这边，续跑状态**只保留还在列表里的行**：会话活过来、那行从「最近」里消失时，
  它的状态跟着清掉；等它再被关掉、回到历史里，是干干净净的，不会带着上一次的
  「已提交」。

### 上一版（1.3.4）已有的

- 改过的会话名字，关掉之后不会丢（不再退回成一串会话编号）。
- 续跑回来的会话在面板里只出现一条。
- 「已提交，等终端上报」超过 30 秒会改口说「还没等到终端上报，可以再试一次」。
